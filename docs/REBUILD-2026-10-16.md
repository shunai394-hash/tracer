# TRACER unified commerce rebuild

This branch starts a compact canonical commerce core instead of another layer of channel-specific gates.

## One flow
1. Import supplier products and variants from configured supplier APIs.
2. Store Japanese catalog data separately from supplier product/variant identity.
3. Calculate the selling price from source cost + shipping + channel/payment fees + target margin.
4. Publish the same canonical product to BASE and Shopify, keeping channel state independent.
5. Intake orders idempotently by (channel, external_order_id); resolve each line through its saved channel listing and supplier variant.
6. Submit the supplier order, persist external acknowledgement, then persist tracking and reconcile.

## Separate listing from fulfillment
Catalog publication is a catalog-data decision. Supplier ordering is a separate, order-time decision requiring a real supplier product ID and variant ID, current sufficient stock, JP shipping, confirmed orderability, and tracking support. Do not infer an internal product ID from a SKU string.

## Database
Apply `supabase/migrations/20261016175000_unified_commerce_core.sql` after review. Tables use the `tc_` prefix to validate the new core without dropping unrelated objects. RLS is enabled without public policies; server-side service credentials are required.

## Secrets
Keep credentials only in deployment environment variables. Required integrations include Supabase URL/service role, CJ credentials, BASE API/OAuth credentials, Shopify shop/admin token, and webhook secrets. Never commit secret values.

## Test
Run `node --experimental-strip-types --no-warnings --test scripts/rebuild-commerce-core.test.mjs` on a supported Node version.
