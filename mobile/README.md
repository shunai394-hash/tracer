# TRACER Native Mobile Shell

TRACER is a Next.js server application. The mobile app is a native Capacitor shell around the deployed TRACER web application; the existing web/server architecture is not converted to static export.

## Current status

- Web/PWA icons already exist in `app/icon.tsx`, `app/apple-icon.tsx`, `app/icon-192/route.tsx`, and `app/icon-512/route.tsx`.
- No native `ios/` or `android/` project is committed yet.
- Native projects must be generated by Capacitor on a machine with the required Apple/Android toolchains.
- Do not change the existing Next.js deployment model just to create the mobile shell.

## Bootstrap

From the repository root:

```bash
npm install
npm install @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android
```

Set a real reverse-DNS application ID before generating the native projects. Do not use a placeholder for a store submission.

PowerShell:

```powershell
$env:TRACER_MOBILE_APP_ID="YOUR.REAL.REVERSE.DNS.ID"
node scripts/bootstrap-mobile.mjs
```

The script:

1. checks that the application ID is explicitly supplied;
2. creates `capacitor.config.json`;
3. runs `npx cap add ios --packagemanager SPM`;
4. runs `npx cap add android`;
5. leaves the existing Next.js project untouched.

Capacitor's current documentation recommends adding the iOS and Android platforms with the Capacitor CLI. New iOS projects use Swift Package Manager by default in current Capacitor releases. See the official documentation before changing native project settings.

## Important

The native projects are generated artifacts and should be committed after generation so Xcode/Android Studio configuration can be reviewed and store metadata can be versioned.

For iOS App Store submission, the final bundle identifier and signing/team settings must be configured in Xcode. For Google Play, the final application ID, signing key, versionCode, and release configuration must be configured in Android Studio/Gradle.

The existing TRACER icon design is the source of truth. Native icon asset generation should use that design rather than creating a second unrelated logo.

## Development architecture

```
iOS / Android
    |
    | Capacitor native shell
    v
TRACER web application
    |
    +-- Next.js server routes
    +-- Supabase
    +-- Stripe
    +-- BASE
    +-- supplier integrations
```

Do not put supplier secrets, Stripe secrets, Supabase service-role keys, or other server credentials into the native application.
